# Screen and endpoint inventory

This inventory records what the frontend ships, what was removed in the "backend-integrated only" cleanup, and why. Source for backend status: `angi-backend/.docs/ANGI_API_Design_Ver1.8.xlsx` (sheet "Backend API") checked against the backend controllers. The `docs/` copies of the API Design and Data Dictionary are older than the `.docs/` ones.

Rule: a screen stays only if its data and actions come from a backend operation that exists. There is no demo mode, fixture data, mock service, placeholder screen or fallback to sample data in product code. The only non-backend page is the public homepage, whose examples are labelled as unsaved.

## Proxy allowlist (`/api/backend/...`)

`GET me`, `PATCH me`, `PUT me/password`, `GET|POST|PATCH owner/restaurant`, `PUT owner/restaurant/business-hours`, `PUT owner/restaurant/operating-status`, `GET|POST owner/restaurant/verifications`, `POST owner/restaurant/verifications/{id}/resubmit`, the owner menu operations validated in `shared/api/owner-menu-proxy.ts`, `POST media`, `GET tags`. Everything else answers `404 ROUTE_NOT_FOUND`. Public read endpoints (dishes, restaurants, Home) were removed from the proxy together with their pages.

## Backend operations not used by the frontend

Operation IDs are those of the API Design workbook ("Backend API" sheet). "Implemented" reflects the backend controllers at the time of this change.

| Operation IDs                                                   | Backend         | Why the frontend does not use them                                                                                                                                                            |
| --------------------------------------------------------------- | --------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| HOME-01, DISH-01..03, REST-01..04 (public discovery and detail) | Implemented     | The previous FE screens ignored the real responses and rendered sample data. They were removed instead of keeping a fake integration; rebuild them against the real responses when scheduled. |
| PREF-02, PREF-03 (preference survey), IMP-01 (impressions)      | Implemented     | The previous FE flows were simulated and are not connected to a real screen.                                                                                                                  |
| NOTI-01..03, RM-01..14, REV-01, REP-01, REP-02, BLOG-01..11     | Not implemented | No endpoints to integrate.                                                                                                                                                                    |
| OWN-19, OWN-20 (owner review replies)                           | Not implemented | No endpoints to integrate.                                                                                                                                                                    |
| MOD-_, ADM-_, OPS-*                                             | Not implemented | No endpoints to integrate.                                                                                                                                                                    |

## Partial integrations

- Account: display name, phone, bio and password only. No avatar upload.
- Google sign-in: rendered only when `NEXT_PUBLIC_GOOGLE_CLIENT_ID` is set.
- Homepage taste and roadmap examples: editorial, never saved, no backend call.
- Maps: owner location picker only; needs a public `pk.` Mapbox token, otherwise manual coordinates and geolocation are used.
